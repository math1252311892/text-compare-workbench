# 中文文本工具箱：文本比较与网文分析

本仓库提供两个可以直接在浏览器中使用的中文文本工具：**文本比较工作台**用于查看两份文本之间的修改，**网文文本智能分析系统（文析）**用于统计小说文本、追踪目标词汇、整理原文证据与书评素材。

两个工具均采用静态 HTML 页面，核心计算在访问者自己的浏览器中完成，不需要注册工具账号、配置 API 密钥或搭建后端。工具名称中的“智能”指分段、匹配、统计及交互辅助，当前版本没有接入大语言模型，也不会自动理解小说情节或生成语义判断。

## 二、文本比较工作台

### 2.1 工具定位

文本比较工作台帮助你回答：“两份文本到底哪里不一样？”它适合文章修改、书评润色、论文文字校对、译稿修订和长文本版本核对。

页面采用左侧功能导航和右侧工作区布局。输入、差异正文、修改清单与统计共用同一份比较结果，切换面板不会清空已经输入的文本或重新计算。

### 2.2 第一次使用

1. 打开[文本比较工作台](https://math1252311892.github.io/text-compare-workbench/)。
2. 在左侧输入框粘贴原始文本，在右侧输入框粘贴修改后的文本；也可以从“导入文本”分别导入两份 TXT。
3. 日常文章对照可先使用默认的“智能比较”。需要逐字检查时，选择“字符级”，并关闭忽略大小写、空白和标点的选项。
4. 点击顶部“开始比较”，或按 Ctrl / ⌘ + Enter。
5. 在结果区查看红绿标记，使用顶部上一处、下一处按钮逐项检查。
6. 从左侧进入“修改记录”“差异统计”或“相似文本片段”，按需要复制结果或导出报告。

想先了解界面，可点击“载入示例”或“试用示例文本”。

**输入或比较规则改变后，请重新点击“开始比较”。** 现有结果是上一次计算的快照，界面会提示结果需要更新；未重新比较时，导出的也是旧快照。

### 2.3 五种比较模式

| 模式 | 适合的场景 | 实际处理方式 |
| --- | --- | --- |
| 智能比较 | 日常文章、书评、长短不一的稿件 | 根据文本规模与换行结构选择词语、句子或段落粒度 |
| 字符级 | 短句、精细校对、检查单字和标点 | 精确计算成功时，直接展示最短字符编辑路径 |
| 词语级 | 希望修改区域更完整、更易读 | 先按词语对齐，再细化内部字符变化；中文优先使用 Intl.Segmenter |
| 句子级 | 检查句子表达、句间增删 | 先对齐句子，再查看句内差异 |
| 段落级 | 长文章、章节、多个段落的修改 | 先比较段落结构，再逐步细化修改内容 |

粗粒度对齐的目的是让结果更便于阅读。它与数学上的最短编辑距离是两项不同的工作：展示路径可能比最短路径包含更多操作，界面会分别标明。

句子切分依据常见句末标点、分号和换行，并非语言学意义上的完整句法分析；英文缩写、小数等可能被切开。段落模式按换行划分并保留空行。

### 2.4 如何阅读差异

- **红色背景、删除线**：原文中被删除或被替换的内容。
- **绿色背景、下划线**：修改稿中新增加或替换后的内容。
- **普通文字**：相同内容，默认不进行大面积高亮。
- **虚线标记**：字面不同，但按当前忽略规则被视为等价的内容。
- **当前修改区域提示**：用于定位正在查看的这一处修改。

“左右对照”分别显示两篇文本；“统一差异”把删除和新增放在同一条阅读流程中，适合连续浏览修改过程。

点击正文中的修改区域，可以联动定位另一侧对应区域。对于单侧插入或删除，工具使用占位与对齐位置帮助定位。同步滚动可以在“差异显示设置”中关闭。

| 修改记录 | 按新增、删除、替换／组合筛选；查看修改前后内容、位置与上下文；定位正文 |
| 差异统计 | 查看两侧字符数、匹配字符、新增、删除、替换、修改区域、最短距离与相似度 |
| 相似文本片段 | 设置最小长度，查看真实连续匹配及两侧位置，定位和复制片段 |

输入区与结果区之间的分隔线可以拖动，也支持键盘调节。收起输入区后可以集中阅读结果。侧边栏支持收起，窄屏上采用抽屉导航；主题可以在浅色与深色之间切换。

### 2.6 编辑距离与相似度的含义

工具使用字符级 Levenshtein 编辑距离：插入、删除或替换一个比较字符的代价均为 1。

设参与比较的两段文本长度分别为 m、n，精确最短编辑距离为 D：

- 当 m 和 n 均为 0 时，相似度为 100%。
- 其他情况下，相似度 = (1 − D / max(m, n)) × 100%。

例如，“你好”变为“您好”需要替换一个字符，D = 1，较长文本有 2 个比较字符，字符相似度为 50%。

**这个百分比反映字符编辑接近程度，不代表语义相似度、文章质量或抄袭判定。** 同义改写可能得到较低字符相似度；字符高度接近的句子也可能表达不同含义。

字符单位优先采用 Unicode 字素簇，尽量把组合字符和组合 Emoji 视为一个用户可见字符。缺少 Intl.Segmenter 时会降级为 Unicode 码点并提示；工具不执行 NFC 正规化，因此视觉上相同但编码不同的文本仍可能被判为不同。

各模式都会尝试独立计算字符最短距离。超过精确计算预算时，仍可提供明确标识的阅读对齐，但不会把启发式结果写成严格最短距离，也不会给出基于该距离的精确相似度。

统计中的新增、删除、替换和匹配数量来自展示路径；“替换字符”按前后字符对计数。“修改区域数量”是连续修改的阅读分组数量，不等于字符操作数。展示路径的操作代价不一定等于另行计算的最短编辑距离。

### 2.7 忽略规则与相似片段

| 选项 | 比较时的处理 | 使用时需要知道 |
| --- | --- | --- |
| 忽略英文大小写 | 将 A–Z 与相应的小写字母视为等价 | 不是所有语言的大小写折叠 |
| 忽略空白字符差异 | 从比较序列中排除空格、制表符、换行等空白 | 原始输入和正文展示仍保留这些内容 |
| 忽略标点差异 | 按 Unicode 标点类别排除标点 | 不会一并忽略数学符号或 Emoji |

开启忽略规则后，距离、相似度和相关计数使用处理后的比较序列；界面同时说明排除数量。原始文本字符数和参与比较的字符数可能不同。

“相似文本片段”提取的是**已经对齐且逐字相同的连续内容**，不根据语义推测共同文本，也不是查找所有可重排的公共子串。默认最短长度为 6 个字符，可自行调整；调整后需要重新比较。位置从原文中的第 1 个字符开始计数，插入点可能位于文本末尾后一位。

### 2.8 导入、导出与快捷键

TXT 导入支持 UTF-8、GB18030 / GBK、UTF-16 LE、UTF-16 BE，优先识别 BOM。浏览器文本框会将 CRLF 换行规范化为 LF，空行和段落结构仍会保留。

| 操作 | 结果 |
| --- | --- |
| 导出 TXT 报告 | 统计、完整两侧文本、修改清单和相同片段 |
| 导出 HTML 报告 | 包含双栏与统一差异的高亮报告，无脚本、无外部资源 |
| 复制差异摘要 | 比较模式、指标及计算口径 |
| 复制修改清单 | 修改前后内容、位置及上下文 |
| 复制完整报告 | 当前计算快照的完整文字报告 |

| 快捷键 | 功能 |
| --- | --- |
| Ctrl / ⌘ + Enter | 开始比较 |
| Alt + ↑ / ↓ | 上一处／下一处差异 |
| Alt + I | 收起／展开输入区 |
| Alt + B | 收起侧栏或打开移动端导航 |
| Esc | 关闭移动端导航抽屉 |

计算优先在 Web Worker 中运行，可以取消。当前版本对两段输入合计设置了 100 万 UTF-16 单元的资源保护上限；这不是“100 万汉字以内一定能精确计算”的承诺。精确计算还受运算预算限制，长文本及大范围重排可能触发降级，超大稿件宜按章节处理。

## 三、网文文本智能分析系统

### 3.1 工具定位

网文分析工作台围绕“导入正文—配置目标—统计分布—回查原文—整理证据—导出报告”组织工作，适合小说阅读研究、人物出场观察、设定词汇统计、书评资料整理。

它帮助你寻找和组织证据。人物身份、事件含义、关系性质、性格评价与剧情结论，仍需要你结合上下文判断。

### 3.2 从一份 TXT 开始

1. 打开[网文分析工作台](https://math1252311892.github.io/text-compare-workbench/novel-analysis/)，点击“文本分析”。
2. 在“导入正文”中选择 TXT，或直接粘贴正文。文件和粘贴文本同时存在时，以最后修改的输入为准。
3. 进入“正文清理”，按需检查、预览并应用清理；不需要清理可直接下一步。
4. 在“目标词汇”中添加人物、地点、物品、功法或其他设定分组。每行一个目标，同一行用空格分隔别名。
5. 在“筛选设置”中按需填写“必须包含的字或词”和停用词。
6. 进入“运行与导出”，点击“开始分析”。
7. 查看高频字串与词汇分布；需要进一步研究时，展开侧栏“研究工具”，访问章节、人物、引用、时间线和书评。
8. 保存项目或导出报告。

也可以点击首页“载入示例”，载入演示文本和目标分组，再点击“开始分析”。顶部步骤按钮可以直接切换，已有输入会保留。

### 3.3 正文、编码与清理

TXT 文件支持自动识别编码，并提供 UTF-8、GBK / GB2312、GB18030、Big5 选项。自动模式优先识别 UTF-16 BOM，尝试 UTF-8，失败时使用 GB18030 推断；乱码时需要手动切换编码，自动识别并非总能准确判断。

当前文件入口面向 TXT；PDF、Word 和 EPUB 应先转换为纯文本。

“文本分析 → 正文清理”可以检查含网址的行、疑似推广内容、作者附言、重复段落和重复章节。操作顺序是：

1. 检查候选内容。
2. 勾选确实需要删除的片段，必要时回查原文。
3. 生成并核对预览。
4. 应用已选清理，再重新运行统计。

清理依据的是规则匹配，不保证每个候选都应删除。应用后会改变当前工作区正文，并使原统计失效；可以撤销最近三次清理。原 TXT 文件不会被直接覆盖。清理会改变文本位置及正文识别码，已有引用仍被保留，但不应将旧位置直接当成清理后的位置。

### 3.4 目标分组与人物别名

例如，创建“人物”分组，每行填写一个目标：

    林舟
    陆遥 阿遥
    掌柜

再创建“线索”分组：

    星图
    北塔
    古井

“陆遥 阿遥”这一行会作为一个目标统计，两种称呼合并计数。人物、地点、物品等都可以使用同样的目标机制。

匹配规则是：**同一个目标内部，别名按最长优先、非重叠方式进行字面匹配；不同目标独立统计。** 如果同一别名被放入多个目标，可能被分别计数，工具会给出重复提示。匹配不会自动识别代词、“主角”等语义称呼或同名异人。

“人物与别名校正”支持检查重复称呼、编辑别名、合并选中人物、拆分目标，先预览调整再应用。修改目标或别名后，需要重新生成相关统计。

### 3.5 高频字串

此功能统计连续的 2、3、4、5 个汉字，适合发现反复出现的表达、姓名片段和候选专有词，不保证每条结果都是完整词语。需要统计完整的人名或设定时，请将其加入“目标词汇”。

- 使用滑动窗口统计连续汉字，允许重叠出现。
- 标点、空白、英文和数字等非统计范围字符会隔断字串，不会把两侧汉字直接拼接。
- 单字和多字停用词也会形成分隔；不会跨停用词制造新的连续字串。
- 由同一个字重复构成的字串会被排除，例如“哈哈”“哈哈哈”。
- 可以按搜索词、最低次数和页大小查看结果，点击字串可定位原文，也可将其加入目标或停用词。
- “必须包含的字或词”最多填写 5 个连续汉字，只限制高频字串，不限制人物目标统计。更长的短语应作为目标词汇填写。

### 3.6 人物概览与词汇分布

“人物概览”根据已配置的目标统计出现次数、各别名命中次数、首次和最后出现的位置，以及覆盖章节数量。可按分组或关键词筛选，并回查正文。

“词汇分布”提供以下视图：

| 图表 | 主要观察内容 |
| --- | --- |
| 章节趋势 | 各章中的出现次数或每万汉字次数 |
| 折线图 | 目标在全文不同位置的提及变化 |
| 堆叠面积图 | 多个目标的分布趋势 |
| 旭日图 | 层级结构中的目标分布 |
| 热力图 | 目标与分段位置形成的分布矩阵 |
| 漏斗图 | 目标总频次的比较 |

支持的等分图表可以切换为 10、20、40 段，已生成的图表可下载为 PNG。全文等分按原始 JavaScript 字符串位置划分，即 UTF-16 单元位置，不是按情节阶段、自然段落或等量汉字划分。

人物提及次数不等于有效出场次数、剧情重要性或战斗力。某个名字也可能出现在回忆、对白和他人的转述中，重要结论应结合原文核对。

### 3.7 章节洞察与共同提及

章节自动识别针对独立成行的常见标题，例如：

    第一章 雪夜
    这里是本章正文。

    第二章 北塔
    这里是下一章正文。

当前规则主要覆盖“第……章／节／回／卷”形式，标题长度与格式也会影响识别。标题和大段正文写在同一行、非标准目录或其他语言的标题可能识别不到。可以在“章节洞察”中修改标题、合并相邻章节，或查找原文中的某行并以此拆分；也可重新自动识别。没有可用章节时，可先使用全文等分图表。

章节洞察包括：

- **章节对比**：选择范围 A、范围 B 和词汇分组，比较绝对次数与每万汉字次数。
- **同章出现**：查看两个目标在哪些章节都被提及，按共同章节数排列。
- **共同提及**：进一步限定为同一句、同一段，或以目标 A 的每次命中为中心的前后字数窗口，查看并收藏原文证据。

“同章出现”和“共同提及”都不等于真实互动、人物关系或事件因果。窗口模式中的重叠窗口会分别计数，不应直接把窗口数量解释为独立场景数量。句段划分同样依赖标点与换行规则。

### 3.8 引用素材库

高频字串或目标词汇的上下文结果可以收藏所在段落；“章节洞察 → 共同提及”的证据也可以加入素材库。v1.15 不再提供独立阅读页面、拖选阅读内容收藏或高级段落搜索。

“引用素材库”保留实际原文片段，允许添加标签、备注和分类，支持筛选、批量分类、拖动或箭头排序，以及导出 Markdown。分类包括人物经历、性格表现、人物关系、世界观和伏笔等。收藏与正文识别码关联，默认围绕当前文本展示，也可查看其他文本以前保存的收藏。

网文工具中的原文位置主要使用从 0 开始的 JavaScript UTF-16 索引，不应与文本比较工具从 1 开始的字素字符位置混用。

### 3.9 人物时间线与书评工作台

“人物经历时间线”以引用素材作为事件证据。选择人物、阶段和原文引用，填写事件概述与备注，即可按原文位置整理经历并导出 Markdown。

事件概述由使用者填写，工具不会自动概括人物经历。可选的“故事时间”是人工备注，列表排序依据原文位置，不自动推断倒叙、插叙或故事内的真实时间先后。

“书评工作台”支持建立人物稿与书评稿，按前期经历、中期经历、后期经历、性格表现、人物关系、总体评价等栏目组织文字。可以查看相关章节、插入原文证据和人物时间线，添加主题标签，并导出当前稿件为 Markdown。

草稿会保存在当前浏览器，也可包含在项目文件中。这里提供的是带证据入口的写作工作区，不是自动生成书评的 AI 聊天功能。

### 3.10 正文定位

统计上下文、人物位置、清理候选和引用中的“定位正文”或“回到原文”会切换到“文本分析 → 导入正文”，在已有正文输入框中选中对应文字。定位本身不修改正文，也不触发重新统计。修改输入后，原结果会失效，需要再次分析。

人物别名的“查看原文”定位到当前称呼之一的首次命中；书评中的章节定位选中该章开头。已有引用仍需加载与它所属正文相符的项目才能准确定位。独立阅读与多文本对比已从 v1.15 移除。

每万汉字次数 = 命中次数 ÷ 对应范围汉字数 × 10000。当前“汉字数”按 U+3400–U+9FFF 范围统计，不包括英文、数字、标点、Emoji，也不覆盖全部 CJK 扩展区；它与文本比较工具的字素字符数不同。

### 3.11 导出文件与范围

| 导出入口 | 格式 | 内容与范围 |
| --- | --- | --- |
| 导出摘要 Excel | XLSX | 目标分组、每种字串长度频次前 100 项、分析说明、可用的章节出场次数，以及 10／20／40 段分布 |
| 高频字串：导出完整 CSV | CSV | 本次分析产生的全部 2–5 字字串，遵循分析时的停用词和“必须包含”条件；不按当前页、页面搜索和最低次数进一步缩小 |
| 图表：下载 PNG | PNG | 当前已经生成的图表 |
| 引用素材库：导出 Markdown | Markdown | 当前筛选范围内的引用、来源位置、标签与备注 |
| 人物时间线：导出 Markdown | Markdown | 当前文本的时间线事件与关联证据 |
| 书评工作台：导出当前稿件 | Markdown | 当前选中的人物稿或书评稿 |
| 分析报告 | HTML／浏览器打印 | 选择的统计、图表、引用、时间线、稿件和备注 |
| 导出配置／导入配置 | JSON | 词汇分组、停用词和字串筛选设置 |
| 保存项目／打开项目 | JSON | 配置、章节修正、引用、研究内容和可选的完整正文 |

Excel 是摘要，不是完整字串数据库；需要全量字串结果时，应选择“导出完整 CSV”。

### 3.12 如何生成分析报告

1. 完成正文分析；如果报告需要章节对比，先生成对应结果。
2. 在“词汇分布”中打开希望收入报告的图表。
3. 进入“分析报告”，选择综合分析、人物分析、整本书评或章节对比模板。
4. 设置标题、备注和各项内容，选择字串的收录范围，并勾选需要的图表。
5. 预览后导出 HTML，或使用“打印／保存 PDF”调用浏览器打印功能。

字串可选择各长度前 20 项或全部筛选结果。尚未生成的数据会在页面和报告中标记为缺项，不会被自动补齐。报告中的图表以图片形式保存；报告可以独立打开，但它不替代可恢复工作状态的项目文件。

## 四、两个工具配合使用

以“研究一部小说并完成书评”为例：

1. 在网文分析工作台导入小说，检查正文编码与章节结构。
2. 配置主要人物及其别名，观察提及频率和不同章节中的分布。
3. 对感兴趣的趋势回查原文，收藏能支持判断的片段，并填写备注。
4. 用人物时间线整理经历，用书评工作台组织观点，导出草稿。
5. 将初稿与修改稿放入文本比较工作台，检查改动、遗漏和表述变化。
6. 导出修改报告，并保存网文研究项目与最终书评。

两个工具通过 TXT、复制粘贴和导出文件衔接；当前没有自动互通正文、引用或分析结果的功能。

## 五、数据保存、隐私与运行环境

### 本地计算与联网部分

两个工具的核心文本处理都在浏览器中执行，没有上传正文进行分析的后端接口。访问在线网站时需要从 GitHub Pages 下载网页资源。

文本比较工具没有外部脚本或样式依赖，下载其完整 HTML 后可在支持相关浏览器能力的环境中离线使用。

网文工具当前通过 jsDelivr 加载两个固定版本的外部组件：

| 组件 | 版本 | 用途 |
| --- | --- | --- |
| SheetJS / xlsx | 0.18.5 | 导出 Excel 文件 |
| Apache ECharts | 5.5.0 | 绘制词汇分布图表 |

外部组件加载失败时，部分图表或 Excel 导出会不可用。网文工具的完整离线使用还需要将这些依赖本地化，不能只下载 HTML 就假定全部功能离线可用。

### 哪些内容会保留

| 数据 | 文本比较工作台 | 网文分析工作台 |
| --- | --- | --- |
| 输入的完整正文 | 不自动持久化 | 不自动持久化 |
| 界面和分析设置 | 部分偏好保存在当前浏览器 | 目标分组、停用词等配置保存在当前浏览器 |
| 引用片段、备注、时间线、书评草稿 | 不适用 | 随相应保存操作保存在当前浏览器，也可导出项目备份 |
| 跨设备同步 | 没有内置云同步 | 没有内置云同步；可通过项目文件迁移 |
| 包含全文的备份 | 导出比较报告含两侧文本，但报告不是可导入会话 | “保存完整项目（含原文）”包含当前正文 |

**“保存设置与收藏（不含全文）”仍会包含已经收藏的原文片段。** 重新打开这类项目时，需要重新提供匹配的正文；“不含全文”不等于文件中完全没有原文内容。

浏览器本地存储不是永久备份。清理网站数据、使用隐私窗口或更换浏览器后，保存的设置与草稿可能不再可用。重要研究请主动导出项目；报告适合阅读和分享，项目适合恢复工作。

### 长文本运行

两个工具使用 Web Worker 分担主要计算，但仍受设备内存、浏览器能力、文本规模和目标数量影响。取消操作可以终止耗时任务；超长小说可按卷、章节或研究问题拆分处理。

网文工具的图表和 Excel 需要相应外部组件加载成功。浏览器对剪贴板、本地存储、下载和弹窗的权限，也可能影响复制与导出。

## 六、常见问题

### 网站显示 404 怎么办？

先确认使用的是本 README 顶部的在线入口，而不是 GitHub 仓库的源码页面。如果刚提交或更新文件，等待 Pages 完成部署后再刷新。维护者也可检查仓库 Settings → Pages 的发布分支及 Actions 中的部署状态。

### 为什么修改文本后，比较结果没有自动变化？

比较结果按计算快照保存。修改输入或比较规则后，需要再次点击“开始比较”，导出也会使用最近一次完成的计算结果。

### 为什么最短编辑距离显示“未计算”，相似度显示“不适用”？

该次输入超过了精确计算预算，工具采用阅读对齐继续展示差异。可以缩小比较范围或按章节分批比较；不能把展示路径的代价直接当成最短距离。

### 为什么忽略空白或标点后，正文里仍然看得到它们？

忽略规则只改变比较序列，不改写原始输入。保留这些内容是为了准确展示原稿。

### 为什么高频字串里有看起来“不像词”的项目？

高频字串统计连续的 2–5 个汉字，不进行词义判断。想按完整的人名、地名或设定统计，请将它们加入“目标词汇”，并按需填写别名。

### 为什么人物次数与手工数出来的不一样？

检查别名是否完整、是否把同一称呼放进多个目标、是否有同名异人，以及手工统计是否只计算真实出场。工具按字面匹配统计提及；同一目标内部使用最长优先、非重叠匹配。

### 为什么章节数为 0？

自动识别依赖标题格式。先确认标题独立成行，类似“第一章 雪夜”；标题与整段正文放在一行时可能无法识别。也可手动修正章节，或改用全文 10／20／40 段分布。

### 为什么 Excel 里的字串没有网页结果那么多？

摘要 Excel 每种字串长度只收录频次前 100 项。全量数据请用“高频字串 → 导出完整 CSV”。

### 为什么报告里没有某张图或某项统计？

先生成对应结果，并在“词汇分布”打开所需图表，再回到报告页勾选。报告不会自动替你运行所有分析，缺项会明确说明。

### 为什么重新打开网站后，小说正文没有了？

完整正文不自动保存。需要继续长期项目时，请保存含原文的完整项目；只保存设置与收藏时，重新打开后要再次导入匹配正文。

### 为什么图表或 Excel 导出不可用？

检查外部图表和 Excel 组件是否加载成功，以及浏览器是否阻止相关资源或下载。Excel 组件不可用时，可以先导出相应 CSV；这不需要 Excel 组件。

## 八、验证范围与使用边界

### v1.15

已运行：三个内嵌脚本语法检查、唯一 DOM ID 和删除功能残留引用检查；9 项实际 Worker/清理/恢复函数检查（包含 13 万字符样本）；正文定位的 CRLF、CR、Emoji 索引与边界检查；报告汇总、字串生成、标题转义和说明移除检查。上述函数测试在 Node VM 运行，不等同于浏览器布局测试。下方 v1.1 的验证记录仅说明历史版本的检查范围，不能当作 v1.15 已验证所有功能。

### 历史验证记录


文本比较工具在开发阶段进行过算法和边界、编辑路径还原、Unicode、展示数据、报告转义及界面状态逻辑检查。具体记录和本机算法自检入口位于工具的“使用说明”。这些自动检查不等同于所有浏览器、屏幕尺寸和权限环境的完整验收。

v1.1 已执行三个内嵌脚本的语法检查、唯一 DOM ID 与五步/六图结构检查；在 Node VM 中执行实际 Worker 和相关函数，验证章节与别名统计、高频字串查询、清理范围、重叠区间处理、应用与撤销还原、多文本目标对比、原文搜索、v1 项目旧字段兼容，以及 13 万 UTF-16 单元样本的统计。主统计 Worker 与 v1 保持一致。Node 检查不等同于浏览器布局或全部导出格式验收。

v1.1 发布后，已在真实浏览器中验证：首页与文本分析导航、五步切换、正文输入、两条清理候选识别、清理预览与应用、撤销后完整还原正文、示例载入和高频字串统计（195 汉字、6 个目标、73 种二字字串）、折线图渲染、漏斗图切换，以及包含图表的 HTML 报告预览。报告已确认不再包含“完整词语”选项或内容。

移动端与不同桌面尺寸、全部研究模块、所有导出文件格式、完整项目导入流程及极长小说场景未做全面回归测试；v1 项目兼容检查覆盖恢复函数中的旧字段处理，不等于所有历史项目均已逐一验证。

本 README 根据当前仓库实现编写。请把统计结果视为回查和分析文本的辅助信息：字符接近不等于语义一致，人物提及不等于实际互动，词频变化也不直接给出作品评价。最终结论应当能够回到原文证据进行核对。
